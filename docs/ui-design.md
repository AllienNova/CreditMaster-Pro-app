### Dark Mode Support

- **Strategy**: Class-based (`darkMode: "class"` in Tailwind config)
- **Toggle**: `ThemeToggle` component (`src/components/ui/ThemeToggle.tsx`)
- **CSS**: `html.dark` class triggers dark theme CSS variables
- **Design principle**: Never pure black -- uses Slate tones (`#0F172A` base)
- **Color adaptation**: All semantic tokens have separate dark mode values for accessibility

## Accessibility

### Implemented Features

Based on codebase analysis:

1. **Semantic HTML**: Components use proper HTML elements (buttons, forms, headings)
2. **Focus Management**: `--ring` CSS variable provides consistent focus ring styling (Vital Green)
3. **Color Contrast**: Dark mode uses Slate tones (never pure black) with brightened semantic colors for WCAG compliance
4. **Font Rendering**: Anti-aliasing enabled (`-webkit-font-smoothing: antialiased`)
5. **Reduced Motion**: CSS animations use `transform` and `opacity` only (GPU-accelerated, less jarring)
6. **Error Boundaries**: `ErrorBoundary` component (`src/components/error/ErrorBoundary.tsx`) prevents full-page crashes
7. **Empty States**: `EmptyState` component (`src/components/ui/EmptyState.tsx`) provides meaningful feedback
8. **Loading States**: `Loading`, `LoadingSkeleton`, `Skeleton` components for perceived performance
9. **Offline Support**: `OfflineIndicator` and `OfflineQueueStatus` components inform users of connectivity
10. **Security Headers**: CSP and X-Frame-Options configured in middleware

### Testing

- **Playwright** (16 E2E specs): Browser journey tests
- **Cypress** (21 specs): Route and API validation
- **Testing Library** (component tests): Uses semantic queries (`getByRole`, `getByText`)

### Gaps

- No explicit `aria-*` audit tool configured in CI
- No Lighthouse a11y score threshold enforced in CI
- No `prefers-reduced-motion` media query handling in CSS animations
- No screen reader testing documented
